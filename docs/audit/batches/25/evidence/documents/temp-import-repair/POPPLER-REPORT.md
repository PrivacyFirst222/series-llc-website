# Remove undeclared Python test dependency

The mandatory document harness used Python pdfplumber, which the repository workflow does not install. This is corrected entirely inside the existing declared check script. It now uses the existing pdftotext executable for text and word boxes and the installed @cantoo/pdf-lib library to decode actual PDF content streams and read stroked line coordinates. No dependency or workflow was added; no product source changed.

This is a fixture-specific geometry reader, not a general PDF parser. It handles the renderer’s newline-delimited operators, graphics-state save/restore and affine transforms, and straight stroked m/l/S paths. Table-border transforms are honored. Rotated pages, unreadable content streams, mismatched page counts and unbalanced graphics state fail explicitly. It does not claim general support for arbitrary third-party PDF operators, forms, or curved paths. Actual client PDFs here are generated by the renderer under test.

Preserved behavior: all 43 assertion labels, conditions and outcomes match the earlier green and red runs; baseline 2559e18 remains 19/43 (24 intended failures), current is 43/43. Current was repeated in three fresh temporary-directory processes and once with explicit evidence output. No Python interpreter was invoked by those runs.

All 24 output PDFs were compared with the retained pdfplumber readbacks: page counts, candidate horizontal-rule counts, recognized signature counts, following printed-word arrays and in-bounds verdicts match; signature coordinates match within 0.000001 point. Non-whitespace extracted text matches. Poppler correctly separates some tightly justified words that pdfplumber joined, so extracted JSON whitespace is not byte-identical. See poppler-comparison.json. Prior rendered visual inspection remains applicable because all product-source hashes are unchanged.

Scoped ESLint and TypeScript checks passed (the typecheck includes the repository’s server/md.d.ts). Early setup results retained: an invocation from repository root used the wrong script-relative path; initial helper rejected table-border transforms and was corrected to apply matrices; the first scoped typecheck omitted md.d.ts and reported only Markdown import declarations. These are harness/setup iterations, not product failures.

Evidence: poppler-final-default-1/2/3.log; poppler-final-explicit.log and directory; poppler-final-baseline.log; poppler-comparison.json; poppler-lint.log; poppler-typecheck-final.log. Source hashes: ../source-hashes-poppler-followup.json.
